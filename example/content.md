# 起點：為什麼我要把講義做成網頁
> 與其讓 AI 每次重新生成一份漂亮但難維護的成果，不如先做出一套能長期重複使用的講義模板。

## 這次分享的背景

### 🎤 從一場 AI 開發工作流分享開始
- 在台大分享如何把 AI 導入工程師日常的開發工作流
- 原本可以用傳統 PPT 準備講義，但這次刻意改成用 Vibe Coding 做網頁
- 目標不是炫技，而是驗證講義是否能變成一個真正可維護的產品

### 💡 為什麼想改用講義網站
- 介面可以依需求量身打造，不受投影片版型限制
- 同一份內容可以同時支援電腦、平板、手機與 PDF 輸出
- 如果做得夠穩定，未來新課程只要替換內容就能快速複用

### 🧱 第一個關鍵決定
- 先接受 AI 很擅長幫你產出第一版
- 但真正有價值的是後續能不能持續修改、維護、擴增
- 所以這次的核心問題不是「怎麼快速生成」，而是「怎麼把成果留下來」

[tags]
- [green] 目標不是做一次性的展示頁，而是建立長期可用的模板
- [blue] 網頁講義同時兼顧排版自由度與跨裝置閱讀體驗
- [orange] 如果內容與結構無法穩定維護，再漂亮也很難落地
[/tags]

> **Vibe Coding 的價值，不該只停留在第一版生成速度**
> 真正拉開差距的是，你能不能把成果整理成之後還能反覆使用的工作流。

# 實作：先用 Codex 產生第一版網頁
> 先讓 AI 幫你把想法變成可看的成果，再回頭找出哪些地方需要制度化。

## 準備工作區與環境

### 📁 先給 AI 一個明確工作區
- 先準備一個空資料夾，讓 AI Agent 有清楚的作業範圍
- 可在編輯器中開啟資料夾，或直接拖曳進工作區
- 這能減少 AI 在不相關檔案中來回游移的機率

### 🟢 先確認 Node.js 可用
- 這次的示範會用到 Node.js 來安裝 Codex 與執行腳本
- 若電腦尚未安裝，建議先用 NVM 管理版本
- 使用 NVM 的好處是未來更容易升級與切換不同版本

```prompt [label="環境檢查與安裝"]
node -v
nvm -v
nvm install --lts
node -v
```

### 🧰 安裝 Codex
- Node.js 就緒後，即可透過 npm 全域安裝 Codex
- 登入方式可選 ChatGPT 帳號、裝置代碼授權，或 API Key
- 如果是一般教學與日常使用，直接登入 ChatGPT 帳號通常最順手

```prompt [label="安裝 Codex"]
npm i -g @openai/codex
codex
```

## 先讓 AI 幫你做出一版

### 📝 提示詞的三個設計重點
- 先明講成果形式，只要單一 HTML，方便部署與分享
- 再說明風格方向，例如日系感、漸層、區塊層次
- 最後補齊資訊架構，例如標題、標語、目錄、社群連結與章節層級

```prompt [label="生成第一版講義網站"]
請扮演熟悉 AI 主題授課的講師，以「Agent Skills」為主題設計講義
講義用純 html 網頁（CSS/JS 都放裡面）呈現
日系風格的設計感，部分文字與背景可以搭配適當的漸層
開頭會根據內容呈現標題，然後下面有發人深省的標語
會根據不同層級與意圖呈現對應的區塊（ex: 大小標題、陳述、列點、流程）
最後放上社群連結鼓勵大家訂閱（FB/YouTube/Medium）
側邊欄會有對應的目錄，方便跳轉到對應位置
```

### 👀 第一版的價值與限制
- AI 生成的第一版通常已經足夠好看，也能快速拿來預覽
- 如果只是做一次性的展示頁，這一步其實已經很有生產力
- 但只要你開始在意措辭、段落、節奏與細節，問題很快就會浮現

# 痛點：為什麼只改 AI 對話或 HTML 都不理想
> 當調整成本開始上升，代表你需要的不只是更好的 prompt，而是更好的內容結構。

## 兩種常見調整方式都有限制

### 🎲 只靠對話調整的問題
- 每次請 AI 修改，都可能順手改動其他地方
- 即使方向對了，措辭與版面仍有高度隨機性
- 你很難精準控制某一小段內容，而不影響整體輸出

### 🪛 直接改 HTML 的問題
- HTML 是最終輸出格式，不是最舒服的內容維護格式
- 對講師或內容作者來說，維護文案、列表與章節會變得很笨重
- 就算本身會寫程式，也會在細節修改上付出不必要的心力

> **不能把可維護性寄託在 AI 每次都剛好懂你**
> 若內容未被抽離成清楚的資料結構，後續維護就只能在 prompt 與 HTML 之間痛苦拉扯。

## 所以答案不是重生成，而是建立模板

### 🧩 模板的核心價值
- 不讓 AI 每次從零開始，而是讓它依照既有規格填內容
- 將風格與排版固定，把調整焦點拉回講義本身
- 只要模板穩定，新主題就能以更低成本複製成功經驗

[flow]
1. 先用 AI 產出第一版，驗證視覺方向與資訊層級
2. 找出容易反覆修改的內容區塊
3. 把這些區塊抽象成可編輯的 Markdown 規則
4. 建立腳本，讓 Markdown 穩定轉成 HTML
[/flow]

# 模板化：把內容維護移回 Markdown
> 如果你想掌握內容，最好的做法是維護中介格式，而不是直接維護最終輸出。

## 逆向設計一套 Markdown 規格

### 📐 不是單純改成 Markdown 而已
- 目標不只是把 HTML 轉成純文字
- 更重要的是先定義哪些內容是標題、步驟、列點、圖片、註解與流程
- 一旦規格清楚，未來任何一份新講義都能用同一套結構生產

```prompt [label="把 HTML 工作流逆向成 Markdown 模板"]
我希望剛剛生成出來的網頁，是可以透過 Markdown 格式編輯內容的
請幫我將網頁結構拆解（列點、步驟、圖片、表格、註解）、分層次（大標、中標、小標），並以常見的 Markdown 語法來設計規則
最後建立一個腳本，我只要編輯 Makdown 文件，網頁的 HTML 就會及時改變
操作方式寫在 README.md 文件中，並建立 package.json
```

### ⚡ 做完之後，日常維護會發生什麼改變
- 內容編輯回到熟悉的 Markdown，而不是卡在 HTML 細節
- 腳本負責把 Markdown 穩定渲染成網頁，降低人工排版成本
- 講義調整可以變成小步快跑，而不是每次都重做整頁

### 🔄 即時預覽帶來的差別
- 只要修改 Markdown，HTML 就能跟著即時更新
- 講師可以用內容作者的思維工作，而不是前端工程師的思維
- 這種分工方式才適合在多個課程主題之間反覆複用

[tags]
- [green] 內容與呈現分離後，修改成本大幅下降
- [blue] Markdown 是講義維護層，HTML 是最終發佈層
- [purple] 腳本讓每次輸出更穩定，不必重新描述整份設計
[/tags]

# 封裝：把模板變成可重複使用的 Agent Skill
> 當流程已經夠穩定，就該讓 AI 幫你自動執行，而不是每次重新口述步驟。

## 建立一條完整工作流

### 🧠 Skill 要解決的不是單一步驟
- 使用者提供主題或講稿後，Skill 先理解主題與輸入內容
- 再根據既定 Markdown 規則產出結構化文件
- 最後透過腳本生成 HTML，形成可交付的課程頁

```prompt [label="建立 Agent Skill 的需求"]
根據下面需求在「.agents」資料夾建立 Skill：
- 參考模板：根據剛剛腳本設計的規格，建立明確的 Markdown 使用規範
- 觸發時機：使用者提供初步想法想建立網頁時，會觸發這個 Skill
- 執行順序：這個 Skill 會先深入研究輸入的主題，再根據規範設計對應的 Markdown 文件；最後把 Markdown 文件透過腳本生成 html
- 特別提醒：預計會有多個主題，所以觸發時，請先建立新的資料夾，裡面存放新生成的 Markdown 與 HTML 檔案；並且建立獨立的 scripts 與 references 資料夾，確保可單獨執行
```

### 🗂️ Skill 完成後的專案結構
- `SKILL.md` 定義名稱、描述、觸發時機與執行規範
- `reference/` 放格式規則與參考樣板
- `scripts/` 負責 build、dev 與其他可執行流程

### 🧪 驗證 Skill 是否真的可用
- 拿一個新主題重新測試，而不是只驗證原始案例
- 確認新資料夾能獨立生成 Markdown、HTML 與必要資產
- 檢查修改後的內容能否持續被穩定維護，而不是只成功一次

## 編輯器與終端機只是不同入口

### 🖥️ 終端機模式
- 適合直接下指令、快速完成 build 與操作流程
- 對熟悉 CLI 的工程師來說，效率通常更高

### 🧭 編輯器外掛模式
- 適合初學者用圖形化介面逐步上手
- 可以更直觀地切換模型、調整思考深度與查看檔案脈絡
- 重點不是哪個入口比較強，而是哪個入口更符合你的工作習慣

### 🛠️ 一個更長期的學習策略
- 不要把焦點只放在某一款 AI 工具最不最強
- 更值得培養的是切換不同 AI Agent 時，仍能維持生產力的能力
- 真正可遷移的是工作流與設計方法，不是單一產品名稱

[summary]
- 🧭 **先做第一版** | 先用 AI 把視覺與架構跑出來，確認方向是否成立
- 🧱 **找出痛點** | 一旦發現 prompt 難精修、HTML 難維護，就代表該抽象化
- ✍️ **改維護 Markdown** | 把內容改放在中介格式，讓腳本負責穩定輸出
- 🤖 **封裝成 Skill** | 將主題研究、內容整理、build 流程整合成可重複使用的工作流
- 🚀 **累積可複用資產** | 讓每次 Vibe Coding 都成為下一次更快、更穩定的基礎
[/summary]
